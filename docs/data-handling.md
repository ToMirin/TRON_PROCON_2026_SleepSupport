# 音声の取り扱いと保存形式

[READMEに戻る](../README.md)

## 通常動作で扱うデータ

マイクの音声は装置内のRAMに取り込み、音の検出とAI推論のために一時的に使用します。通常動作では、音声波形をmicroSDへ録音したり、ネットワークで外部へ送信したりしません。

| データ | 用途 | 保持・出力先 |
|---|---|---|
| PCM音声 | 音量計算と1秒入力の作成 | RAMのリング・入力バッファ |
| Log-Mel特徴量 | AIモデルへの入力 | RAM内の作業領域 |
| 分類結果 | SNORE・COUGHの記録 | RAM、停止後にmicroSDのCSV |
| 状態・診断情報 | 操作表示と開発時の確認 | LCD・シリアル端子 |

リングや作業領域は後続処理で再利用します。処理直後に全領域をゼロ消去する設計ではなく、使用済み音声がRAM上に一時的に残ることがあります。

設定中、開始前のGood Night表示中、Delay中は音声取得を開始しません。監視開始後に取得を始め、停止操作で停止を要求します。

## シリアル出力と開発用録音

現設定では `STORAGE_DEBUG_READBACK=1` となっており、保存成功後にCSVをmicroSDから読み戻してシリアル端子へ出力します。PCなどでログを取得すると、時刻・イベント・分類スコアがその接続先にも残ります。通常動作のこの読み戻しで音声波形を送ることはありません。

CSV読み戻しを無効にする場合は、[storage.c](../Application/storage/storage.c)の `STORAGE_DEBUG_READBACK` を0にしてビルドします。他の状態・診断メッセージまで一括で無効にする設定ではありません。

別途、開発用の個別テストには音声をPCへ転送してWAV化する機能があります。通常システムのイベント記録とは異なる処理です。通常操作にはWAV録音機能を割り当てていません。

## CSVのファイル名と書式

microSDのルートへ、`EVT00001.CSV` から `EVT99999.CSV` の連番で保存します。既存のCSVと一時ファイルの両方を調べ、空いている番号を選びます。

以下は書式例です。

```csv
time,event,value
23:59,START,
23:59,SNORE,184
00:01,COUGH,119
00:02,STOP,
```

| 列 | 意味 |
|---|---|
| `time` | 時刻。24時間表記の `HH:MM` |
| `event` | `START`、`SNORE`、`COUGH`、`OVERFLOW`、`STOP` |
| `value` | SNORE・COUGHは分類スコア、OVERFLOWはRAM上限による破棄件数、START・STOPは空欄 |

ヘッダは `time,event,value`、改行はCRLFです。OTHERの行や音声データそのものは出力しません。

### 分類スコア

SNORE・COUGHの `value` は `confidence_q8`（0〜255）です。選択クラスのINT8出力に128を加えた値で、おおよそのモデル出力は `value / 256` です。

例えば184なら `184 / 256 = 0.71875` です。音量、音圧レベル、イベント回数を表す数値ではありません。現在はスコアの高低にかかわらず、選択クラスがSNORE・COUGHなら記録対象にします。

## 時刻の決め方

RTC（電池等で時刻を維持する時計）は使用せず、設定した時分とμT-Kernelの経過時間を使います。

```text
現在時刻 = 設定したHH:MM + 時刻設定を確定してからの経過時間
イベント時刻 = セッション開始時刻 + sample_position / 16000 秒
```

`sample_position` は音声のトリガー位置を示す64 bit値です。推論が完了した時刻やSDへの書き込み時刻を、イベント時刻として使うことはありません。STOPは利用者が停止操作をした時刻です。

CSVは分単位で、日付と秒を含みません。午前0時をまたぐと23:59から00:00へ周回します。ファイルの日付・更新日時はファイルシステムの固定設定に依存し、画面で設定した時計とは連動しません。

## 保存上限と欠落の扱い

SNORE・COUGHを1件16 B、最大1,024件までRAMに保持します。START・STOPはこの音響イベント枠とは別に出力します。

上限を超えた場合は、先に記録したイベントを保持し、新しいイベントを破棄します。破棄件数があれば、STOPの前に次のような行を出力します。

```csv
07:00,OVERFLOW,12
07:00,STOP,
```

この例の12はRAMログの容量超過で破棄した件数です。音声の欠落、入力バッファ不足、推論失敗、記録通知の混雑による欠落をすべて集計する値ではありません。CSVだけから取得・処理の全欠落を復元することはできません。

## 保存と再試行

監視中はRAMに保持し、停止後にまとめて保存します。

1. `EVTnnnnn.TMP` へCSV全体を書き込みます。
2. 書き込みを終えてファイルを閉じます。
3. `EVTnnnnn.CSV` へ改名し、保存成功とします。
4. 次のセッションを開始できる状態に戻します。

保存失敗時はRAMと割り当て済みのファイル番号を保持し、SW1で同じセッションを再保存できます。TMPが残っていても完成済みCSVと区別できますが、書き込み中の電源断への完全な保護や自動復旧を保証するものではありません。

保存前の電源断・リセットではRAMログが失われます。CSV自体は平文で、暗号化やアクセス制御は行いません。カードやシリアルログを共有するときは、イベント時刻も含まれることを踏まえて扱ってください。

学習用音声の出典と取り扱いは[学習データセット](datasets.md)、通常操作は[利用ガイド](usage.md)を参照してください。
